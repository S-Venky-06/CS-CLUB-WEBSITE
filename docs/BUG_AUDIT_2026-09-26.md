# Bug audit — 26 September 2026

## Coverage and limits

The inventory contains 172 tracked files: 137 text files and 35 raster assets. Automated checks read every tracked file, validated applicable JSON, inspected raster metadata, and checked literal member/moment asset references. TypeScript compilation covered both applications. Behavioral review concentrated on authentication, registration, admin operations, repositories, navigation, initialization, exports, and database scripts. Dependencies, generated build output, and private environment files were not treated as project source.

This is not a claim that every possible defect is eliminated. No live database writes, payment transactions, email sends, deployment, or database migrations were performed. Browser visual regression and live Google OAuth have not been exercised.

## Fixed

| Area | Defect and correction |
| --- | --- |
| Authentication | Signed bearer tokens never expired. Tokens and sessions now enforce a 24-hour login lifetime; malformed payloads and future timestamps are rejected. |
| Authentication | An invalid bearer token could fall back to an authenticated cookie. Invalid bearer credentials now remove the request's authenticated session user. |
| Authorization | Unknown roles passed a comparison against `undefined`. Role checks explicitly reject unknown and inherited object keys. |
| Authorization | Demoted administrators retained permissions in old tokens. Protected admin requests resolve the current stored role, with environment-defined seed roles taking precedence. |
| Configuration | Production could start with a public default signing secret. Missing, short, and documented placeholder secrets now prevent production startup. |
| CORS | Similarly named Vercel deployments were automatically trusted. Allowed deployment origins must now be explicitly listed in `FRONTEND_URL`. |
| API client | The global fetch override could miss child mount effects, discard Request headers, or match a lookalike URL prefix. Explicit API calls attach credentials immediately and compare URL origin/path boundaries. |
| API configuration | Most pages requested `undefined/api/...` when configuration was absent. All callers share a localhost fallback and normalize trailing `/api` or `/api/v1`. |
| Validation | Parsed defaults and sanitized fields were discarded. Handlers now receive the parsed body. |
| Registration validation | Fractional/negative team sizes and mismatched or duplicate team rolls were accepted. Teams are now bounded to four participants and validated against their member list. |
| Legacy registration | The non-checkout endpoint accepted paid events and discarded team details. It now accepts only free events, respects registration closure, preserves members, and writes `FREE`. |
| Admin input | Unknown roles, string booleans, invalid display orders, duplicate attendance, and arbitrary payment status values could reach storage. Schemas now validate these operations. Attendance also checks membership in the selected registration. |
| Events | Creating events discarded the supplied location. It is now persisted. Attempts to change an event ID are explicitly rejected. |
| Event editor | UTC timestamps were displayed as local input and shifted on save. The editor now converts stored instants to local wall time. Invalid date conversion is within error handling. |
| Registration reads | One malformed optional JSON cell could crash the complete listing; some read methods omitted email status. A shared parser validates arrays, preserves legacy attendance, and includes email status consistently. |
| Registration filters | Team view ignored event, attendance, branch, and payment filters. Both views now use the appropriate filters; individual search includes teammates and roll numbers. Counts, empty states, and export availability reflect the active view. |
| CSV export | A `#` in a data URI could truncate a download; numeric values could crash escaping. Blob downloads preserve data, normalize values, escape quotes, and neutralize spreadsheet formula prefixes. |
| Dashboard | Metrics and connection status were hardcoded. The overview now loads actual records and displays loading/failure states. |
| Activity log | Registration filtering recognized an old action name only. It now includes current attendance, payment, and email-resend action names. |
| Navigation | Home/About links on legal pages stayed on the wrong route. Links now route to the home page. Missing skip-navigation targets were added. |
| Event popup | The popup pointed at a nonexistent section and advertised a live event when fetching failed. It now uses the correct target and requires an active event with an unexpired deadline. |
| Animation lifecycle | A button component declared inside render remounted on every state change. It is now declared at module scope. The hero counter's initial timeout is also cleaned up. |
| Startup loader | Initialization could continue after skipping or navigating away. Pending requests and retries now stop when the effect is cancelled or the loader is skipped. |
| Error handling | Malformed JSON and oversized bodies were reported as server failures. They now produce 400 and 413 responses. |
| Email templates | User-controlled content was interpolated directly into HTML. Text fields are now HTML escaped. |
| Database tools | Bootstrap headers and the activity sheet name disagreed with repositories. New sheets use the current schema; existing sheets are not silently relabeled. Two obsolete row-repair scripts that would corrupt current data are disabled. |
| Framework/assets/docs | Removed the unsupported Next.js development indicator option, replaced a missing favicon reference, and corrected setup environment names and Node requirements. |

## Remaining findings

### Payment flow — high priority, not modified

`backend/AGENTS.md` requires Cashfree-specific skill files before integration edits: “The moment a task turns into real Cashfree integration work … follow the 'Before You Start' section” of `.agents/skills/cashfree-skills/getting-started/SKILL.md`. Those files were absent from the workspace and searched user skill locations. The payment controller, SDK configuration, and webhook implementation were therefore reviewed but left unchanged. Generic API transport, validation, and UI lifecycle changes do not validate the integration itself.

1. **Retry amount can disagree with the saved team.** `createOrder` reuses an existing pending registration, but calculates the next order amount from new request data without updating or comparing the persisted team. A retry with a smaller team can confirm the larger original roster for a smaller amount. Persist immutable order/registration details and validate amount, currency, and ownership when confirming.
2. **Capacity blocks pending-payment retries.** The pending row counts toward capacity, so a participant holding the last slot cannot retry a failed checkout. Pending reservations also have no expiry.
3. **The main checkout ignores `registrationOpen`.** The setting is now enforced by the legacy free registration service, but the payment controller has a separate rule implementation, including for free events.
4. **Provider identifiers can exceed limits.** Order IDs embed an event-derived registration ID plus a timestamp, and customer IDs embed the email plus a timestamp. Verify supported identifier limits and use bounded identifiers with durable mappings.
5. **Payment return route is admin-only.** The configured return URL targets `/dashboard/registrations`, which ordinary registrants cannot access. A comma-separated `FRONTEND_URL` also cannot be used directly as a return URL.
6. **Confirmation work is not durable or idempotent.** Verify/webhook paths can repeatedly send mail; asynchronous email work may stop after a serverless response. Verification sends the previously fetched registration object, which can still contain `PENDING`. Use a durable idempotent confirmation/outbox operation.
7. **Raw-body routing and webhook failures need dedicated tests.** Raw parsing is selected by a case-sensitive prefix in `app.ts`, while Express routes are not case-sensitive by default. The webhook handler reports storage failures as signature failures. Test provider retries and route variants with signed sandbox payloads.

### Storage and operations

- Google Sheets read-then-append does not provide atomic duplicate prevention or capacity reservation across concurrent processes. A transactional datastore or distributed reservation mechanism is needed; a local mutex would not fix serverless concurrency.
- Bearer logout removes the browser token and cookie session, but a copied token is still usable until expiry. Immediate revocation requires shared server-side token/session state. Express MemoryStore also does not provide durable cross-instance cookie sessions.
- Several repositories silently turn upstream failures into empty lists/default settings, and Sheets reads have fixed upper row bounds. Large datasets and upstream outages need explicit handling.
- The public member showcase and social links are static; admin roster visibility/order and club social settings are not wired into those public components. The Members worksheet lacks the image and specialty fields needed to reproduce the showcase without a data migration.
- Historical architecture/API/performance documents and `frontend/SUMMARY.md` describe some features or states no longer present. Treat current routes, types, and this audit as the implementation reference.
- Frontend lint still fails on existing `any` types, synchronous state changes inside effects, unescaped JSX text, and unused code. These are not all runtime bugs. The backend advertises an ESLint command but has no ESLint dependency/configuration; its TypeScript build and new regression command are usable checks.

## Verification

- Backend TypeScript build passes. All 14 regression tests pass (11 backend/API tests and 3 frontend utility tests), using mocked Sheets and disabled external credentials.
- Frontend production build succeeds, generating all 16 routes. The first restricted-network attempt failed to download Google Fonts; the permitted network-enabled build succeeded without changing the font design.
- Initial frontend lint: 44 errors and 54 warnings. A subsequent run after the first fixes reported 40 errors; remaining lint debt is explicitly not marked as passed.
- Tracked-file checks found no malformed applicable JSON, unreadable raster metadata, or missing literal member/moment asset references.
- `git diff --check` passes.

## Deployment effects

- Configure a unique production `SESSION_SECRET` of at least 32 characters and list all allowed frontend/preview origins in `FRONTEND_URL`.
- Tokens older than 24 hours require sign-in again. Admin requests now depend on a current role lookup unless the account is configured as an environment seed administrator.
- Existing Sheets data is not migrated by this patch. Back up and explicitly migrate legacy schemas; do not re-enable the retired repair scripts.
- No dependencies were added. Run `npm test` in `backend` and `npm run build` in `frontend` to repeat the executable checks.
